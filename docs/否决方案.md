## 一、全局禁改清单（核心架构底线）

以下事项为项目既定架构核心，任何未经用户明确指示的重构或变更均属违规：
1. **A/B/C 三区模型**：严禁合并、扁平化或破坏三区分离与目录隔离语义。
2. **fail-closed 安全底线**：破坏性操作（删除/移动/隔离）在元数据不可信、mapping 冲突或 API 异常时必须放弃执行。
3. **`check_exists()` 三态语义**：仅 `True` 视为存在，`False` 视为权威不存在，`None`（不可信）必须 fail-closed 退出。
4. **数据库单例与路径**：`bridge.db` 与 `tmdb_watchlist.db` 固定位于项目根目录，WAL 模式与分词器依赖严禁破坏。
5. **WebUI 认证与 IP 绑定**：PBKDF2-HMAC-SHA256、会话 IP 绑定与 LAN 白名单第一道防线严禁削弱。
6. **TMDB 业务核心**：待看列表与本地媒体三级匹配验证逻辑保持稳定。

## 三、代码注释与稳定锚点（Grep 索引规范）

全库采用四类半角冒号/方括号的稳定注释锚点，禁止使用过往计划编号前缀：

| 锚点格式 | 适用场景 | 语义说明 |
| :--- | :--- | :--- |
| `# 设计决策:` | 有意的安全/架构/算法决策 | 明确禁止反向重构，说明设计初衷。 |
| `# 有意保留:` | 测试 helper、扩展预留字段、幂等清理 | 说明保留目的，防止被当作死代码删除。 |
| `# 已知取舍:` | 边界明确、代价受控的工程权衡 | 说明触发条件与接受理由，防止过度设计。 |
| `# [已废弃]` | 机制迁移/重构后的旧入口与兼容说明 | 标明迁移去向与保留兼容的范围。 |

**代码检索规范**：
审查代码时，使用 `grep "# 设计决策:"`、`grep "# 有意保留:"`、`grep "# 已知取舍:"`、`grep "# \[已废弃\]"` 即可快速定位所有特殊设计，结合本登记册即可完成闭环核对。

### A 区快照采信门 ctime 第五维

**决策·已处置（原有意取舍关闭）** ｜ 代码位置：`domain/sync/sync_service.py:process_strm_file`

否决替代方案：逐文件内容哈希与命中后二次抽读（STRM 正文为单行短文，等价取消跳检）、仅 bump parse_version（一次性全读后窗口重开）、USN 日志/文件系统事件溯源（NTFS 强耦合、需常驻监听）。

### 引擎存活真相唯一单源：复合存活权威，根除 `_app_running` 标量

**决策·现行（根除优于降级镜像）** ｜ 代码位置：`webui/server.py:_engine_is_running`、`app_service_core.py:is_engine_running`、`webui/server.py:stop_main`、`webui/server.py:get_main_status`、`webui/routes.py:_handle_restart_webui`

PR#2 第 7 轮根修裁决，两条决策：

1. **复合存活权威（唯一单源）**：「引擎是否在跑」的一切决策与展示（start_main 准入闸、stop_main engine_alive 复核、`get_main_status().running`、routes 重启停机门与 main_running、`main()` 退出是否 stop_main）一律读复合权威——引擎侧 `AppService.is_engine_running()`（observer 真实存活）∨ server 侧「当前启动 worker 线程存活」（覆盖 observer 挂载前的扫描窗）。绝不以 phase 派生 `is_running` 作存活真相：相位可被 `set_phase("stopping"/"fail_safe")` 合法写成谎，phase 说停、真相在跑会造成漏判。svc 缺失或无该方法时退化 worker 存活判 + WARNING，fail-closed 不读相位。
2. **根除优于降级镜像（用户裁决）**：曾考虑把 server 侧 `_app_running` 标量降级为"无读者镜像"保留写入，最终裁决三位一体根除（字段声明 + 全部 9 写点 + 全部 3 读点同轮删除/迁移）。理由：无读者的陈旧标量仍是可被后续代码误读为存活真相的隐患面，且 `get_main_status` 每次读都无锁写回该标量本身即并发缺陷（非原子读-改-写），删除即消除。拒绝路径同时根除"谎报相位"：stop_main 的 worker_alive/engine_alive 拒绝分支不再对真实在跑引擎写 `set_phase("fail_safe")`（仅落 server 侧展示态），fail-closed 语义不变（拒绝伪造停止成功、保留句柄供重试）；`AppService.stop()` 的 `observer.join()` 加 5s 有界超时（与同块字幕 join 对齐），超时不抛错、不谎报停止完成，交 stop_main 复核后拒绝。爆炸半径触达 7 测试相关产物（6 测试文件 + src/tests/README.md）与 dashboard.js 终态错误透出，系根除真实半径，非范围蔓延。

实现口径补充（两条，均 fail-closed 等价）：

3. **start_main 准入闸的相位终态豁免**：准入判定为「复合存活权威在跑 ∧ 相位 ∉ {stopped, fail_safe} 才拒"已在运行中"」——相位处于终态残留时即便权威判在跑（如卡死的旧 worker 兜底为真），也交由下方残留清理路径给出更精确的「旧 worker 未退出 / 引擎复活」fail-closed 拒绝（该路径同样保留句柄、不推进 generation）。两条路径均 fail-closed。取舍理由：不加豁免会让 fail_safe 残留 + 卡死 worker 场景命中笼统的"已在运行"，丢失既有"未退出"拒绝契约的精确语义。
4. **stop_main engine_alive 判据直调 `svc.is_engine_running()`**（与 start_main 残留复核经 `_engine_is_running()` 封装的口径并存）：svc 缺该方法时 AttributeError 落入既有 `exception` 停止失败分支——fail-closed（保留句柄供重试），不弱化安全性，仅错误文案泛化。

### 审计快照失效失败 → 不完整终态

**决策·现行（fail-closed 且不弱化异常隔离）** ｜ 代码位置：`domain/sync/sync_service.py:initial_scan_a`、`refresh_service.py:_maybe_run_full_audit`、`refresh_service.py:run_full_audit_now`

全量审计对不可解析文件的旧快照行失效（`delete_a_snapshots_batch`）失败时：审计扫描的余下阶段（目录登记、进度、FTS）仍照常完成，但 `initial_scan_a` 在函数末尾抛 `AuditIncompleteError`，调用方据此跳过 `complete_index_generation` / `touch_verified_by_mapping` / `last_full_audit_at` 三项推进（周期路径返回 False 计入健康失败，手动路径返回 `status="incomplete"`）。

理由：已知过期 webdav 链接未被作废却记录"核对完成"，会让后续普通扫描经采信门复用过期链接——把"未作废"当作"已验证"是权威性缺口。跳过时间戳推进使下轮周期/手动审计自动重试，残留行在下轮被清除；不留孤儿状态，也不因单次失效失败阻断 B 区收敛。

边界（有意保留的既有取舍，不随本条目改变）：A 根不可达或 `os.walk` 出错时 keep 集不完整，属"无法观测"而非"已知必须作废"，维持既有"跳过 prune + WARNING + 本轮仍推进核对时间戳"的 fail-open 语义。
