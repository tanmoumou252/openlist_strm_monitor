## 二、N0 架构约束（渲染护栏）

**`isRenderStale()` 这类模块级单变量渲染护栏无法表达"按调用方的代际"**，已废弃并改为 `captureRenderGuard()` 代际快照工厂（`router.js`）：

- 每个异步入口在首次 `await` / `.then()` 之前调用 `captureRenderGuard()`，得到只对自身生效的 stale 判定闭包。
- 后续 agent **勿再退回模块级单变量方案**——无论赋 `myGen`（恒 false，护栏空转）还是 `-1`（恒 true，整站白屏）都是错的。
- 标签切换/刷新不经 router、不推进 `_renderGen`，代际护栏无法拦截"切标签后旧响应回填"；`logs.js` 用模块级 `_logsGeneration` 单独处理。

## 三、注释关键词约定（稳定 grep 锚点）

> 自第 17 轮起，代码注释不再使用计划编号前缀（如 `[已修复] R7:`、`[设计取舍] #10:`、`T2:`、`B3-A:` 等），改为人类可读的**稳定关键词**，供未来 agent 双向定位（grep 关键词 + 读本登记册）。

| 关键词 | 含义 | 原对应标记 |
|--------|------|------|
| `# 设计决策：` | 这是有意的设计取舍，勿按缺陷"修复" | 原 `[设计取舍]` 标记、有意的安全阀/回滚/fail-safe 行为 |
| `# 有意保留：` | 看似死代码但故意保留的字段/分支 | `anime_max_season_diff` 等保留待用字段 |
| （无关键词的普通注释） | 纯行为描述 | 原 `[已修复] X` 与裸编号设计注释剥离前缀后 |

**grep 约定：** 扫描时 `grep "设计决策"` / `grep "有意保留"` 即可发现所有"有意为之"的位置，再对照本登记册查详情，避免误报。登记项按**文件:函数名**索引（而非计划编号）。

1. **新增审计发现时**：先查本文件第一节排除表，若已登记则跳过。
2. **标记为"设计决策"、"非缺陷"或"已否决"前**：在第一节表中补一条，含类别、代码位置与理由。
3. **已修复的缺陷**：不在此登记，记录在 `.kilo/plans/` 对应的计划文件中。
4. **本文件纳入 Git 追踪**，位于 `docs/否决方案.md`。
